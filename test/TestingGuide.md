# 🧪 Game Testing Guide (Beginner-Friendly Edition)

This document is a **simple and detailed guide for testing the game**.  
You do NOT need technical knowledge.  
If something feels wrong, confusing, ugly, or annoying — that is valuable feedback.

You are testing as a **real player**, not as a developer.

---

## 0. Preparation (a.k.a. “Just Be a Human”)

Before you start:
- Open the game
- Assume you know nothing about it
- Do not try to be smart or “help the developers”
- If you feel confused, frustrated, or bored — **that matters**

📌 **Rule:**  
If you think *“This feels weird”* — write it down.

---

## 1. First Impression Test (10-Second Rule)

Look at the game for **10 seconds** and answer:

- Do you understand **what this game is**?
- Do you understand **what you are supposed to do**?
- Do you feel like playing or closing the tab?

📌 **Document if:**
- The purpose of the game is unclear
- You don’t know where to click
- The screen feels overloaded or empty

---

## 2. Visual & UI Testing (How It Looks)

Focus ONLY on appearance.  
Ignore logic and rules for now.

Check:
- Colors (too bright, too dull, painful to look at)
- Text (too small, hard to read, too much text)
- Buttons (do they look clickable?)
- Layout (is anything misaligned or messy?)

📝 **Exercise:**  
Play the game and write down **everything you dislike visually**, even if the reason is:
> “I don’t like how this looks”

📌 **Rule:**  
You don’t need a reason. Personal dislike is valid feedback.

---

## 3. First Gameplay Run (Natural Play)

Play the game **normally**, like you would at home.

Do NOT:
- Analyze
- Overthink
- Try to break things (yet)

Just play.

Write down:
- Moments where you hesitated
- Moments where you didn’t know what to do
- Moments where the game surprised you (good or bad)

📌 **Rule:**  
If you had to stop and think — something is unclear.

---

## 4. Second Gameplay Run (Expectation vs Reality)

Play the game **again**.

This time, compare:
- What you EXPECTED to happen
- What ACTUALLY happened

Answer:
- What works well?
- What works differently than you imagined?
- What feels missing?
- What would make this game better in an ideal world?

📝 **Exercise:**  
Describe your **ideal version of this game**, then mark:
- ✅ What already exists
- ❌ What is missing
- ⚠️ What exists but works badly

---

## 5. Functional Testing (Does It Work?)

Now try to break things (gently).

Try:
- Clicking buttons multiple times
- Playing very fast
- Refreshing the page
- Going back and returning to the game
- Doing “stupid” or unexpected actions

Look for:
- Errors
- Freezes
- Weird behavior
- Messages that don’t explain what went wrong

📌 **Rule:**  
If the game shows an error, it should be **clear and friendly**.

---

## 6. Missing Features Test

Ask yourself:
- Is there something you expected to exist but doesn’t?
- Is there information you wanted but couldn’t find?
- Is there an action you wanted to do but couldn’t?

Write it down even if you’re not sure it’s “important”.

---

## 7. Final Questions (Honest Answers Only)

Answer honestly:
- Would you play this game again?
- Would you recommend it to a friend?
- What is the main reason for your answer?

---

## 8. How to Report Issues (Simple Format)

For each issue, write:

- **Where:** (screen / level / step)
- **What you did**
- **What you expected**
- **What actually happened**
- **Screenshot** (if possible)

Simple words only. No technical terms required.

---

## Final Rule (Very Important)

You are NOT judging the developers.  
You are helping make the game better.

If something annoys you — **that’s a real problem**.
